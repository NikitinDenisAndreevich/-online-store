# Интернет-магазин 

В этом проекте реализованы две основные сущности: `Product` и `Category`.

## Функциональность
- `Product`: хранит название, описание, цену и количество на складе.
- `Category`: хранит название, описание и список товаров `products` (типа `list[Product]`).
- Атрибуты класса у `Category`:
  - `category_count`: количество созданных категорий (суммируется автоматически при инициализации `Category`).
  - `product_count`: суммарное количество товаров во всех созданных категориях (считается как длина списка `products` при инициализации `Category`).

## Новые возможности

### Строковое представление объектов
- `Product.__str__()`: возвращает строку в формате "Название продукта, X руб. Остаток: X шт."
- `Category.__str__()`: возвращает строку в формате "Название категории, количество продуктов: X шт." (где X - сумма quantity всех товаров)

### Магический метод сложения
- `Product.__add__()`: позволяет складывать продукты, возвращая сумму произведений цены на количество
- Поддерживает сложение: `Product + Product`, `Product + число`, `число + Product`
- Пример: товар a (цена 100, количество 10) + товар b (цена 200, количество 2) = 1400

### Наследование (Задание с классами-наследниками)
Созданы два класса-наследника от `Product`:

#### 1. Smartphone (Смартфон)
Класс `Smartphone` расширяет базовый класс `Product` следующими атрибутами:
- `efficiency` (производительность) - описание процессора/чипсета
- `model` (модель) - модель смартфона
- `memory` (объем встроенной памяти) - в ГБ
- `color` (цвет) - цвет устройства

#### 2. LawnGrass (Газонная трава)
Класс `LawnGrass` расширяет базовый класс `Product` следующими атрибутами:
- `country` (страна-производитель) - страна происхождения
- `germination_period` (срок прорастания) - период в днях
- `color` (цвет) - цвет травы

### Ограничения сложения
Доработана функциональность сложения товаров:
- Товары можно складывать **только из одинаковых классов продуктов**
- Попытка сложить объекты разных классов (например, смартфон и газонную траву) вызывает ошибку `TypeError`
- Для реализации ограничений используется функция `type()`
- Пример: `smartphone1 + smartphone2` - работает, `smartphone1 + lawn_grass1` - вызывает `TypeError`

### Защита метода add_product
Метод `Category.add_product()` защищен от добавления объектов, не являющихся продуктами:
- Можно добавлять только объекты класса `Product` или его наследников (`Smartphone`, `LawnGrass`)
- Попытка добавить другой тип объекта (строка, число, список и т.д.) вызывает ошибку `TypeError`
- Для реализации ограничений используется функция `isinstance()`

Реализация находится в файлах:
- `src/product.py` - базовый класс Product

- `src/models.py` - импорты всех классов

Пример использования классов-наследников — в `16.1_main.py`.

## Новая функциональность (Задание 16.2)

### Абстрактный базовый класс BaseProduct
Создан абстрактный базовый класс `BaseProduct`, который определяет общую функциональность для всех продуктов:
- Абстрактные методы: `__init__`, `__str__`, `__add__`, `price` (геттер и сеттер), `get_total_value`
- Класс `Product` теперь наследуется от `BaseProduct`
- Классы `Smartphone` и `LawnGrass` автоматически наследуют функциональность через `Product`

### Миксин LoggingMixin
Реализован миксин `LoggingMixin` для логирования создания объектов:
- При создании любого объекта выводится информация в консоль в формате `ClassName(param1, param2, ...)`
- Миксин добавлен в цепочку наследования класса `Product`
- Работает для всех классов-наследников (`Smartphone`, `LawnGrass`)

### Множественное наследование
Класс `Product` использует множественное наследование:
- `Product(LoggingMixin, BaseProduct)` - правильный порядок для корректной работы миксина
- Все существующие методы и функциональность сохранены (обратная совместимость)

### Новый метод get_total_value
Добавлен метод `get_total_value()` для получения общей стоимости товара на складе:
- Возвращает произведение цены на количество (`price * quantity`)
- Доступен для всех классов-наследников
